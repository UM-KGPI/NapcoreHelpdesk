
## File Structure

### Format
- **Format**: RDF/Turtle (.ttl)
- **Character Encoding**: UTF-8
- **Ontology Namespace**: `https://transmodel-cen.eu/6.2/`
- **Prefix**: `tm:`

### Prefix Declarations

```turtle
@prefix rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#> .
@prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .
@prefix owl: <http://www.w3.org/2002/07/owl#> .
@prefix xsd: <http://www.w3.org/2001/XMLSchema#> .
@prefix tm: <https://transmodel-cen.eu/6.2/> .
```

### Ontology Header

```turtle
tm:TransmodelOntology a owl:Ontology ;
  rdfs:label "Transmodel Core Ontology v6.2" ;
  rdfs:comment "Transmodel v6.2 (2024) - Parts 1-10" ;
  owl:versionInfo "6.2" .
```

### Class Definition Pattern

Each Transmodel class is represented as an OWL class:

```turtle
tm:ROUTE a owl:Class ;
  rdfs:label "ROUTE" ;
  rdfs:comment "A SCHEDULED STOP POINT SEQUENCE along which a public transport SERVICE is operated." .
```

- **Class IRI**: `tm:<CLASS_NAME>` (where CLASS_NAME is the sanitized Transmodel class name)
- **Label**: Original class name from EA model (preserved exactly)
- **Comment**: Class description from EA model's Note field

### Sanitization Rules

Class names are converted to valid RDF identifiers using these rules:

1. Replace non-alphanumeric characters (except underscore) with underscores
2. Prefix with underscore if name starts with a digit
3. Preserve case (original names are UPPERCASE)

**Examples**:
- `ROUTE` → `tm:ROUTE`
- `TYPE OF SERVICE` → `tm:TYPE_OF_SERVICE`
- `3-CYCLE MAINTENANCE` → `tm:_3_CYCLE_MAINTENANCE`

## Integration with NAPCORE System

### Usage in the Helpdesk

Transmodel is the helpdesk's cross-standard pivot: there is no separate upper ontology. NeTEx, SIRI
and OpRa classes are linked to the Transmodel class of the same name by `skos:exactMatch` in
`alignments/transmodel-{netex,siri,opra}-align.ttl` (generated by `build_transmodel_alignment`, see
[`GENERATION.md`](GENERATION.md)). Standard concepts that share a Transmodel class are treated as
siblings during retrieval. This is used in three places:

1. **Live cross-standard expansion**: `backend/helpdesk/services/graphdb_client.py`
   (`query_graphdb_concept_expansion`) pivots through Transmodel classes in GraphDB. Every
   standard-scoped query includes the Transmodel graph and all three alignment graphs.
2. **GraphDB-independent fallback**: `backend/helpdesk/services/semantic_graph.py` parses the same
   alignment files directly at process startup, so expansion still works when GraphDB is disabled or
   unreachable.
3. **Reference definitions**: `backend/helpdesk/services/ontology_evidence.py` returns the Transmodel
   definition of a concept's aligned class alongside the standard's own definition, with the
   `tmalign:transmodelDefinitionStatus` (equivalent / extends / differs) from the alignment files.

### Loading and Querying

1. **Load into GraphDB**: `standards/transmodel.ttl` is loaded into the named graph
   `https://napcore.eu/graph/standards/transmodel`, together with the alignment files and the other
   ontology modules:
   ```bash
   make graphdb-load   # manage.py load_graphdb_ontologies --apply --replace --include-artifact-rules
   ```

2. **Query with SPARQL**: Example query to find all classes in Part 1:
   ```sparql
  PREFIX tm: <https://transmodel-cen.eu/6.2/>
   PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>

   SELECT ?class ?label ?comment
   WHERE {
     ?class a <http://www.w3.org/2002/07/owl#Class> ;
            rdfs:label ?label ;
            rdfs:comment ?comment .
    FILTER(STRSTARTS(STR(?class), "https://transmodel-cen.eu/6.2/"))
   }
   LIMIT 100
   ```

## Validation

### RDF/Turtle Compliance

The ontology is valid RDF/Turtle and can be:

- **Parsed** with any RDF parser (Jena, RDF4J, RDFlib, etc.)
- **Loaded** into RDF triple stores (GraphDB, Virtuoso, Fuseki, etc.)
- **Queried** with SPARQL
- **Reasoned** with OWL 2 DL reasoners

### Validation Commands

```bash
# Validate with rapper (Raptor RDF tool)
rapper -g /path/to/transmodel.ttl

# Load into GraphDB via command-line
/opt/graphdb/bin/graphdb -Dgraphdb.home=/data import -i transmodel.ttl -r ttl
```

## Status

Done (see "Usage in the Helpdesk" above):
- Loaded into GraphDB as `https://napcore.eu/graph/standards/transmodel`.
- Cross-standard alignment: NeTEx, SIRI and OpRa classes are mapped to Transmodel classes, and
  Transmodel is the cross-standard pivot for retrieval.
- Retrieval augmentation: Transmodel definitions are returned as reference evidence next to each
  standard's own definition.

Open ideas, not implemented:
- Expose Transmodel concepts through a REST API (no such endpoint exists today).
- Tag or index FAQ entries against Transmodel class URIs.
- Raise alignment coverage (SIRI and OpRa classes are still mostly unaligned) through
  `alignments/transmodel-alignment-curation.csv`.
